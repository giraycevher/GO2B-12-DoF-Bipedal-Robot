# Accessibility

## Contributor Expectations

Contributors should consider accessibility when developing documentation, software interfaces, and project resources.

When submitting changes that affect user-facing components, please:

- Use clear and readable language in documentation.
- Provide descriptive labels and instructions where applicable.
- Ensure keyboard navigation is supported when developing web-based interfaces.
- Include accessibility considerations in pull requests.
- Test changes on different screen sizes when possible.

## Reporting Accessibility Issues

If you encounter an accessibility barrier while using this project, please open an issue in the GitHub repository.

When reporting an issue, include:

- A description of the problem.
- The affected page, document, or feature.
- Browser and operating system information.
- Any assistive technologies used (optional).
- Steps to reproduce the issue.

Screenshots and recordings are welcome but not required.

### Severity

Accessibility issues may be prioritized according to their impact:

- High: Prevents users from completing essential tasks.
- Medium: Causes significant difficulty but has a workaround.
- Low: Minor usability or readability issues.

### How We Respond

Accessibility reports will be acknowledged within 7 days whenever possible.

Maintainers will:

1. Review and reproduce the reported issue.
2. Determine its severity and priority.
3. Implement a fix when feasible.
4. Provide updates through the GitHub issue.

## Ownership and Maintenance

Accessibility considerations are maintained by the project maintainer.

The maintainer is responsible for:

- Reviewing accessibility-related issues.
- Evaluating proposed improvements.
- Updating project documentation as needed.

## Supported Environments

The project is primarily developed and tested on:

- Windows 10/11
- Ubuntu Linux
- Modern Chromium-based browsers
- Firefox

Accessibility support may vary across other platforms.

## Known Limitations

Known accessibility limitations will be documented in GitHub Issues when identified.

At this time, no formal accessibility audit has been completed.

## Feedback and Improvements

Suggestions for improving accessibility are always welcome.

Please use GitHub Issues or Pull Requests to propose enhancements to documentation, software interfaces, or development practices.
